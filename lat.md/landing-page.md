# Landing page

The static landing page introduces browser.jr without expanding its documented runtime claims.

## Content boundary

The page summarizes current behavior from the README and labels missing JavaScript, protocol compatibility, and browser-window support as limits.

It links to Playwright and agent-browser as compatibility targets while stating that neither protocol is complete.

The hero describes browser.jr as a first-principles Rust browser-engine effort.

## Visual system

The page applies the root `design.md` monograph system with full-width plates, light display type, condensed labels, sharp borders, and one ember status indicator.

The engine-path diagram spans the hero below its heading, summary, and actions.

The compatibility panel gives each target a numbered, linked row and keeps the incomplete-adapter status visible.

## Engine walkthrough

The page explains DOM construction, style resolution, layout, paint, and action evidence through current Rust modules and explicit support boundaries.

## Swarm positioning

The page presents each persistent CLI process as an isolated swarm worker and labels the static-web boundary beside its measured macOS arm64 binary size.

Each claim appears once so the diagram, source links, and benchmark remain the primary explanation.

## Benchmark presentation

The benchmark section pairs recorded full-workflow results with the fixture, session, timing, and correctness rules needed to interpret them.

The result table scrolls horizontally on narrow viewports and exposes a visible scrollbar.

## Delivery

The dependency-free files in `website/` can run through any static file server without changing the Rust crate or command-line runtime.
